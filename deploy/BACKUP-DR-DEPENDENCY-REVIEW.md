# Причина остановки runtime preflight

Read-only проверки VPS 17.11.2026; recovery повторно не запускался.

Исходный журнал указывает dr-privileged.py:110, assert 'not found' not in output.
Полная команда в исходном запуске не записывалась. По единственной воспроизведённой
неразрешённой зависимости в обходе ELF установлена команда:

`/usr/bin/ldd /tmp/karimoff-dr-root.uscdhgmh/work/app/node_modules/better-sqlite3/prebuilds/linuxmusl-x64.node`

Этот тестовый каталог уже удалён. Read-only эквивалент на неизменённом источнике:

`/usr/bin/ldd /opt/karimoff/node_modules/better-sqlite3/prebuilds/linuxmusl-x64.node`

Результат ldd: exit=0, `libc.musl-x86_64.so.1 => not found`.
readelf -d подтверждает DT_NEEDED с этим SONAME, без RPATH/RUNPATH.
Абсолютный путь в ELF не задан: ожидается поиск загрузчиком, а не один фиксированный
файл. Проверенные кандидаты /lib/libc.musl-x86_64.so.1 и
/usr/lib/libc.musl-x86_64.so.1 отсутствуют; /lib/ld-musl-x86_64.so.1 также отсутствует,
ldconfig -p не показывает musl. Это реальное отсутствие зависимости НЕИСПОЛЬЗУЕМОЙ сборки.

VPS: x86_64, glibc 2.39. Код better-sqlite3/lib/binding.js выбирает linux-x64.node
при наличии process.report.header.glibcVersionRuntime. ldd для linux-x64.node exit=0,
все зависимости разрешены. Проверка не импортировала приложение и не открывала БД.
Дополнительно linux-arm64.node и linuxmusl-arm64.node дают ldd exit=1,
`not a dynamic executable` на этом хосте. Глобальный rglob всех prebuilds ошибочен
как критерий готовности runtime для одной платформы.

## Уже выполнено локально

Только диагностика: runtime-dependencies.jsonl теперь фиксирует каждый объект,
точный argv, exit code, missing SONAME, stdout/stderr ldd. Ошибка явно называет объект
и библиотеку; прежний fail-closed сохранён. Фильтрация зависимостей затем исправлена локально по разрешению пользователя; см. ниже.

## Минимальное исправление — только после разрешения

1. Зафиксировать platform/arch/glibc установленного Node без импорта приложения.
2. Для better-sqlite3 выбирать ровно prebuild, определённый его штатным binding.js;
   на проверенном VPS — prebuilds/linux-x64.node. Остальные варианты не включать
   в список обязательных ELF для этого runtime, записывать причину исключения.
3. Не игнорировать `not found` глобально: неизвестные ELF, зависимости выбранной
   сборки, Python/Node/sharp по-прежнему должны приводить к остановке.
4. Не устанавливать musl, не создавать подменяющих symlink и не задавать обходной
   LD_LIBRARY_PATH. Не менять production node_modules.
5. Добавить runtime-dependencies.jsonl в ограниченный экспорт evidence, проверить
   локальные синтаксис и выбор платформы; обновить SHA256 управляющих скриптов.
6. Повторный DR только по отдельному разрешению, с неизменными isolation gates.

## Откат

До исправления сохранить отдельные локальные копии изменяемых файлов и их SHA256.
При отказе от исправления восстановить именно эти локальные файлы; новые root-owned
CONTROL-копии не переиспользовать. При последующем неудачном тесте — штатная остановка
дочернего namespace-процесса, сохранение evidence и проверяемая очистка только нового
тестового каталога по BACKUP-DR-TEST.md. Production-откат, service restart и изменения
пакетов не требуются: production не меняется.

Ограничение доказательств: исходная команда восстановлена по коду и результату
read-only ldd; первоначальный лог не сохранил имя ELF. Новая диагностика устраняет
этот пробел. Дальнейшая работоспособность chroot/namespace/smoke пока не подтверждена.

## Выполненное локальное исправление

Выбор по Node platform/arch/glibc, исключение только известных несовместимых
better-sqlite3 prebuilds, strict fail для отсутствующего выбранного файла,
неизвестной платформы/сборки и обязательных зависимостей. Диагностика сохранена.
4 unit-теста PASS (матрица Linux x64/arm64 glibc/musl, неизвестные платформы,
выбор ELF, отсутствующая сборка, missing SONAME при ldd exit=0, ldd exit=1).
Тесты не импортируют root-координатор: из AST извлекаются только чистые функции.
Исходные файлы для отката: deploy/dr-runtime-review/before/. Для отката восстановить
три сохранённых файла локально; production не требует отката. Linux DR не запускался.
